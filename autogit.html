Early experiment · 08/02/25

Automating a notes repository.

A small exercise in Git, shell scripting, and scheduled tasks.

I wanted a folder of Markdown notes to reach a Git repository without repeating the same manual steps. The first version used a short shell script and a weekly cron schedule.

How it worked

The script entered the notes directory, staged changes, created a dated commit, and pushed it to the remote. Cron ran the script each Monday at midnight. I checked both a manual run and the scheduled run.

What I learned

The shell script was only part of the job. Repository setup, authentication, the working directory, and the scheduler's environment all mattered.

Limits of the first version

The original script staged everything and had little error reporting. A tool I used now would limit which files it includes, handle an unchanged folder, stop when a step fails, and keep an inspectable log. A Git remote also needs a deliberate privacy choice before personal notes are sent to it.
